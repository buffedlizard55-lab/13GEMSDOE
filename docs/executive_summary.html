Whether a rejected upload consumes an allowance is not documented in anything this project could fetch — ask info@drivendata.org before relying on either answer.

Official format requirements

  • Same projected CRS and bounds as training data: EPSG:32611
  • Same resolution: 100 m
  • Data outside the bounds: null or nan (A uses 0.0 instead — see the table above for why and for B)
  • One layer, float32, values between 0 and 1 (higher = more likely a fault)

Official source: DrivenData problem description → Submission format; submission-entry rules: Official Rules PDF.

Before a slot is spent on a different file

The file above is the best local candidate: a fault-blind lattice (every 5th row and column, 4 % of the footprint). It is the repository's best local hold-out map under the frozen R13 rule (18/18 paired folds vs the R11 recipe) and it is a coverage-geometry baseline, not a geological prediction. It is NOT a predicted leaderboard score. It beat the references under the predeclared hide-and-recover protocol (report). That is catalogue recovery on hidden known faults, not the undisclosed new-fault test set, and it is not a leaderboard prediction. A new candidate gets a slot only if it beats the current holdout best under more than one withholding rule on the confirmation folds, its pixels are not an exact duplicate of any earlier map (scripts/make_submission.py blocks that), and the front-door verifier passes. Distinct maps can still round to the same public score — never promise unique scores.
